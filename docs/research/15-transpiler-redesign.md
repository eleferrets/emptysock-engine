STATUS: design, read-only research. ## 0. Summary

- Everything the passes do by text surgery has an AST node or a symbol-table query that already exists (`gml/{lexer,parser,ast,symbols,project-symbols,builtins}.ts`). The missing pieces are: an Emitter, a small set of "lowering" tables (which built-in call becomes which `GmlActions.*` call, currently spread over ~40 regex passes), and the instance-reference flow analysis.
- T-1..T-10, R-2 and R-4 are pass-composition bugs (a later regex sees the output of an earlier one, or matches inside strings/declarators). Emitting from the AST removes the class: no pass ever re-reads generated text.
- The flow analysis is a ~300-line hand-written flow-insensitive, context-insensitive-with-summaries points-to worklist over object indices. No library beats that on this lattice (section 4.7).

## 2. Target architecture

```
.gml text
  -> Lexer (gml/lexer.ts, exists)          tokens + trivia (comments, #region)
  -> Parser (gml/parser.ts, exists)        Program + ErrorStmt regions + ParseDiagnostic
  -> ProjectSymbols (gml/project-symbols)  assets, enums, macros, ObjectInfo, FileFacts, Scope
  -> Flow analysis (gml/flow.ts, NEW)      points-to sets for instance-ref slots
  -> Lowering tables (gml/lower/*.ts NEW)  built-in call/var -> engine shim mapping
  -> Emitter (gml/emit.ts, NEW)            AST -> TypeScript string + source map hints
  -> gms2-codegen (module layout: behavior/script/enum files)
  -> Report (gms2-report): diagnostics, fallback list
```

### 2.2 Error-recovery policy

Parser guarantees statement-level recovery (`recovered` count in `FileAnalysis`). Policy, in order:

1. `ErrorStmt` -> emit `/* GML parse error: <msg> */` plus the original source text as a comment, and a warning entry (`kind:"parse"`, file, range). The rest of the file still emits; module loads (this is what makes the walk tests stop treating load failures as import warnings, T-11).
2. If the error is a known source-bug class (T-12 `place_free(...) {`; GameMaker rejects it too), `gms2-source-bugs.ts` rules run on the token stream BEFORE parsing and return corrected text or a repair edit list; parser then sees valid input. Rules become "token pattern -> edit", not regexes over strings and comments (uses lexer output, so no stripper).
3. If more than N% of statements in a file are `ErrorStmt` (proposed N=50), emit the whole file as a stub module with a single report entry. No legacy text-pass fallback beyond W6-5 (section 6: keeping it forever preserves the bug class). During migration only, `useLegacy` per file is allowed as a flag in the harness, removed at W6-7.
4. Every fallback is a counted line in the import report ("dynamic reads: n", "unresolved: n", "recovered statements: n") so regressions show in the golden diff.

## 3. Semantics mapping

### 3.1 `with`, `other`, `self`, `id`, `all`, `noone`

- `with (target) body`: `target` classification by AST: object asset (`Resolved.symbol.assetKind === "object"`) -> iterate live instances of that type (and children if inheritance is modelled); `self`/`id`-typed expression -> single; `other`, `all` -> `all` instances; `noone` -> no iteration; numeric/instance expression -> `GmlActions.with_each(ctx, expr, (_inst) => {...})` (existing helper). Inside the body a new `with` scope with `FieldSource` = target object's `ObjectInfo` (or unknown => dynamic).
- Body binding: bare instance-variable identifiers inside the body resolve to the WITH TARGET (`via:"with"`), not to the caller. This is the exact GML rule and replaces "with-seeding of object fields" (l.1238). `_withCaller = _entity` is bound so `other` inside the body resolves to it.
- `other`: in collision events, the colliding instance parameter; inside `with`, the enclosing caller; elsewhere `undefined` + warning. Determined by scope kind, not by regex, so `other` in a struct literal key or member name is untouched.
- `self`: `_entity` in event scope; the struct/constructor instance in `struct` scope.
- `id`: `_entity`-based instance id unless it is a member name, struct key, local, or a param named `id` (resolve decides).
- `noone` -> `undefined` (runtime `noone` as -4 is handled by shim comparisons; keep current semantics: `undefined`); as an object argument stays a quoted asset only where `ParamKind` says so.
- `all` -> `"all"` marker for `with`/`instance_destroy`/`collision_*`, resolved by `ParamKind`.

### 3.2 Arrays and accessors

`Index.accessor` decides: `[` array (copy-on-assign semantics honoured by `gmlArr` only where the value flows from a script param, else plain), `[@` direct, `[|` `ds_list`, `[?` `ds_map`, `[#` `ds_grid`, `[$` struct. Store target `a[i] = v` goes through `lowerStore` with `kind=index`; the array-ness of a bare identifier is no longer inferred by name (T-2): it is a property of the `Index` node, so whole-variable assignment `name = v` never reaches the array path. `FieldInfo.isArray` is kept only to decide the default value on first read (`[]` vs `0`).

### 3.3 Structs, constructors, methods, statics

`function C(a) constructor { ... }` -> `class`-like factory returning a struct with `self` bound; `New` -> `new`-call; `inherit` via `: Parent(a)` maps to parent call. Struct methods capture `self` through `.bind`; `method(self, f)` -> `gmlMethod`. `static` is per-constructor prototype storage; top-level static per function, existing rule kept. Struct literal `{a: 1}` keys never resolve identifiers; shorthand values do.

### 3.4 Members (cross-object and local)

`Member(obj, prop)`:

1. `obj` resolves to object asset with `via != lexical` => `getGmlObjectVar(entity, ctx, "obj_x", "prop")` (or component field when `prop` is `x/y/image_*`).
2. `obj` is `global` => `GlobalStore`.
3. `obj` is an expression whose flow set `S` (section 4) is known: emit typed access (3.5 table below).
4. otherwise dynamic `getGmlEntityField(ctx, obj, "prop")` or, for struct values, plain property access (decided by `holdsEntity` in flow: instance vs struct vs unknown).

### 3.5 Runtime shim contract and what static resolution removes

Shims today: `getGmlVar/setGmlVar/setGmlVarDefault/getGmlArrayVar` (`gmlInstanceVars.ts`), `getGmlObjectVar/setGmlObjectVar/getGmlRefVar/setGmlRefVar/getGmlEntityField/setGmlEntityField` (`gmlCrossInstance.ts`), `gmlNum`. The contract the Emitter guarantees: (i) every instance-variable read of an unknown-typed value is `getGmlVar(_entity,_ctx,"n")`; (ii) `gmlNum(...)` is only applied where a numeric context requires it AND the flow/type lattice says the value is not array/instance/struct/string (fixes R-2 by construction); (iii) unknown call => `__unknown`.

What static resolution can remove (in order of safety):

- `getGmlRefVar(entity,ctx,"owner","x")` (does `getGmlVar` of "owner" then dispatch on string/entity/id) => `getGmlEntityField(ctx, <expr for owner>, "x")` when flow set is instance-only. Two lookups become one.
- If the flow set is a singleton `{obj_player}` or all members have the field component-backed: `entity.get(Transform).x` style direct access, guarded by `asLiveEntity`.
- Locals hoisted: a local resolved lexically is a JS `let`, never `getGmlVar` (already true for declared locals).
- `getGmlVar` stays for instance vars because the runtime stores them in a side table (component-backed only for x/y/image_*, per decisions); removal of the side table is out of scope (section 6).

Typed access table: flow set S, field f

| S                                                                 | f   | emit                                                                                      |
| ----------------------------------------------------------------- | --- | ----------------------------------------------------------------------------------------- |
| singleton or all members share component-backed f (x, y, image_*) |     | `(getEnt(owner)).get(Transform).x` (with null guard)                                      |
| all members declare f in `ObjectInfo.instanceFields`              |     | `getGmlEntityField(ctx, owner, "f")` typed `unknown`, wrapped `gmlNum` if numeric context |
| S contains struct or top                                          | any | dynamic `getGmlVar`-based path + report entry                                             |
| S empty (never assigned)                                          |     | `undefined` + `unresolved` diagnostic                                                     |

### 3.6 Local vs object-name shadowing

The concrete ambiguity: a `var`/param/instance field named exactly like an object. Resolution: `Scope.resolve(name)` walks block -> function locals/params -> with-target fields -> object instance fields -> project (assets) -> builtins. If a lexical binding exists it wins and `Resolved.shadowed` lists the asset; the Emitter uses the lexical binding and emits a `shadow` diagnostic. Only if `via` is `project` with `assetKind:"object"` is `obj_x.f` a cross-instance reference. Instance fields named like an object (assigned in `Create`) resolve as `instance` and produce `shadow` too; GameMaker itself resolves the instance variable first, which matches. The old comment at l.5091-5100 ("safe without per-file scope analysis") becomes false-proof: the scope analysis is the mechanism.

### 3.7 `event_inherited`, `gml_pragma`, `script_execute`

- `event_inherited()`: parent object known from `ObjectInfo` (parent field from `.yy`, IN `SourceFile` input; add `parent?: string` to `SourceFile`, small change in `project-symbols.ts`). Emit a call to the parent's same event function (`parentBehavior.onStep(entity, ctx)`); if no parent or parent lacks that event, emit nothing plus a `notice`. Resolves D13.
- `gml_pragma(...)`: compile-time no-op; emit a comment, no runtime call (currently an unresolved identifier).
- `script_execute(script, args...)`: first arg resolved: script asset -> direct call (imports it, fixing R-1's un-imported script values); unknown expression -> `GmlActions.script_execute(ctx, expr, ...)` runtime table lookup by name; flows into the dataflow as a call with `top` callee (section 4.4).
- `argument0..N`, `argument[n]`, `argument_count`: lowered from the enclosing function's param list (legacy style), no text pass.

### 3.8 Macros and enums

Macros: symbol, expanded at `Identifier` (config-scoped keys `Config:NAME`). Enums: `EnumDecl` compile to numeric constants; `Member(EnumName, Member)` emitted as the literal. Both parse errors in old regex (`[^}]*`) vanish.

## 4. Dataflow analysis: instance-reference points-to

### 4.1 Problem

Slots holding an instance reference: object instance variables (`obj_bullet.owner`), locals, script params, script returns, struct fields (treated coarse). Goal: for each slot `s`, `pts(s) ⊆ Objects ∪ {STRUCT, TOP}` where `Objects` are object indices. Examples to solve:

1. `with (bullet) { owner = other; }` in `obj_gun` step: `owner` is a field of the with-target (bullet's type) and the value is `other` = the caller (`obj_gun`). Fact: `field(obj_bullet, owner) ⊇ {obj_gun}`.
2. `var b = instance_create_layer(x,y,"L",obj_bullet); b.owner = id;`: `pts(local b) = {obj_bullet}` from the built-in `returns: instance` with object arg; `b.owner = id` writes `{self_type}` into `field(obj_bullet, owner)`.
3. Reading `owner.x` in `obj_bullet`: `pts(field(obj_bullet, owner)) = {obj_gun}` -> typed access (3.5).

### 4.2 Abstract domain

- Universe: object indices `0..N-1` from `ProjectSymbols.assets("object")`, plus two markers `STRUCT` (any struct/ds/array container) and `TOP` (unknown/number/string/anything else) : the value may be a non-instance too.
- A fact value is a bitset (`Uint32Array`, N/32 words) plus flags. Join = bitwise OR; bottom = empty and no flags. N is at most a few hundred per project, so a set is ~10 words.
- Widening: because the lattice is finite (powerset of N objects), no widening is needed for termination. A size cap is for clarity only: a set with > K (proposed 8) members collapses to `TOP` for emission purposes (typed access requires a small enumerable set); analysis itself keeps the full set.
- Inheritance: an instance of child `C` is assignable to a slot typed by parent `P`; sets store the concrete created type, and `with (obj_P)` expands to `P ∪ descendants` (requires `parent` from 3.7).
- Slots: `field(O, name)` (instance variable of object O), `local(fileId, fnId, name)`, `param(scriptId, idx)`, `ret(scriptId)`, `global(name)`. Struct fields and ds_ containers: `TOP` on store, `TOP` on load (section 4.5).

### 4.3 Transfer functions (per statement/expression, flow-insensitive)

`eval(expr, ctx) -> Value` where ctx = (self type set, other set, enclosing `with` target set).

| Expression                                                                                                             | Value                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Identifier` resolved lexical                                                                                          | `pts(local/param slot)`                                                                                                                                                                         |
| `Identifier` resolved instance (self.f)                                                                                | `field(selfType, f)` (union over self type set)                                                                                                                                                 |
| `Identifier` = object asset (as a value)                                                                               | `{obj}` with flag `isObjectIndex` (from `follow = obj_player;`, runtime `getGmlObjectVar` string case)                                                                                          |
| `id`, `self`                                                                                                           | `selfSet`                                                                                                                                                                                       |
| `other`                                                                                                                | `otherSet` (collision event: the colliding object type from `Collision_obj_x`; within with-body: the caller's self set)                                                                         |
| `noone`                                                                                                                | bottom (does not add types, marks `maybeNull`)                                                                                                                                                  |
| `instance_create_layer/depth/instance_create`, `instance_copy`, `instance_nearest/furthest/find/place/position/id_get` | object-arg position via `BuiltinInfo.params` `asset:object` -> `{that object}`; if the arg is not a constant asset: `eval(arg)`; `instance_nearest(..., obj)` etc. return `{obj ∪ descendants}` |
| user `Call` to script                                                                                                  | `ret(script)` (summary, 4.4)                                                                                                                                                                    |
| `Member(e, f)`                                                                                                         | union over `t ∈ eval(e)` of `field(t, f)`; if `TOP ∈ eval(e)` -> TOP                                                                                                                            |
| `Index`, ds accessors, `array_get`, `ds_*_find*`                                                                       | TOP (4.5)                                                                                                                                                                                       |
| `Conditional`, `??`                                                                                                    | join of branches                                                                                                                                                                                |
| `Assign(target, =, e)`                                                                                                 | store `eval(e)` into slot(s) of target (below)                                                                                                                                                  |
| anything else (arithmetic, strings, calls to unknown built-ins)                                                        | TOP (not an instance) but does NOT pollute a slot unless it is the RHS of a store into a slot already known to receive instances (4.6)                                                          |

Stores (`emit facts`):

- `local = e`, `var local = e`: `local(..) ⊒ eval(e)`.
- `self.f = e` / bare instance `f = e`: `field(t, f) ⊒ eval(e)` for `t` in self set.
- `Member(x, f) = e` where `x`'s pts is `S`: `field(t, f) ⊒ eval(e)` for `t ∈ S`.
- Inside `With(target) { f = e }`: bare `f` resolves via `with` scope: `field(t, f) ⊒ eval(e)` for `t ∈ eval(target)` (the very shape that today's `WITH_BRACE_RE` half-handles).
- `Return e` in script `s`: `ret(s) ⊒ eval(e)`.
- `Call(script, args)`: `param(script, i) ⊒ eval(arg_i)` for each user script call. `script_execute(s, args)`: same if `s` constant, else args flow to all scripts of matching arity flagged as "executed dynamically" (rare; top for their params, report).
- Struct literal `{f: e}` / constructor field: `STRUCT`; fields tracked only when the constructor is a user constructor with a known name (`field(ctorType, f)`), which is the same domain with constructor as a pseudo-object.
- Global `global.g = e`: `global(g) ⊒ eval(e)`.

### 4.4 Interprocedural summary over scripts

Context-insensitive summaries: one `ret(s)` and one `param(s, i)` slot per script. `analyzeFile` yields per script a `ScriptSummary { paramFlows, retFlows }` as constraint lists. Because slots are global cells and constraints are subset edges `a ⊒ b`, the summary is implicit: no cloning, no call strings. Precision loss appears only when one script is used with different object types for the same parameter (both are reported as the union; typed access then needs S size > 1 -> table entry 2 and stays correct).

### 4.5 ds_ and containers

`ds_list_add(l, e)`, `ds_map_add`, array elements, struct fields (except user-constructor fields), `array_push`, `variable_instance_get/set` all treated as TOP on store and TOP on load. Rationale: user asked for "top"; ds structures are the classic unsound-to-track shapes (alias, index dependent). Cost: `owner.x` where `owner = ds_list_find_value(...)` stays dynamic. Report entry per case, so the residual count is visible.

### 4.6 Algorithm: constraint graph and worklist

1. Extraction pass over each file's AST (uses `FileAnalysis.resolve` and `ObjectInfo`): build constraints of two kinds: `Base(slot, value)` (constants such as `{obj_bullet}`) and `Copy(dst, src)` (dst ⊒ src), plus `LoadField(dst, srcSlot, f)` (dst ⊒ field(t, f) for each t ∈ pts(srcSlot)) and `StoreField(dstSlot, f, src)` (field(t,f) ⊒ src for each t ∈ pts(dstSlot)). The last two are the only "complex" constraints (Andersen-style).
2. Solve with a worklist: initialise `pts` from `Base`; pop slot `s`; propagate along `Copy` edges; for each complex constraint attached to `s`, expand new members of `pts(s)` into new `Copy` edges (field slots for the newly seen types); re-add changed destinations. Terminates because each `pts` only grows and is bounded by N+2.
3. Optional: process the graph SCC-wise (Tarjan) for speed; not needed at these sizes.
4. Complexity: with V slots, E edges, N object types, worst case O(V * N * E) bitset operations in theory (Andersen's is cubic); with V ~ few thousand, N ~ few hundred and bitset words of N/32, real cost is far below a second per project (estimate, unverified: measure in step 3 of the sweep). Two passes: (a) build (one AST walk per file); (b) solve.
5. Determinism: worklist ordered by slot id; output sorted so golden diffs are stable.

### 4.7 Soundness stance and output

The analysis is a MAY-analysis (over-approximation of possible types), flow- and path-insensitive. Emission rule: if `pts(slot)` contains no `TOP`/`STRUCT` and is non-empty, emit typed access that is CORRECT for every member (field lookup by name works for all; component-backed direct access requires the field to be component-backed on all members). If the slot also may be a non-instance (number, noone, undefined), guard with `asLiveEntity` (null-safe, same as `getGmlEntityField`). If `TOP`/empty/unknown, emit the current dynamic `getGmlRefVar`/`getGmlVar` path and record `{file, line, slot, reason}` in the report (`dynamic-fallbacks`). So unsoundness can only come from things the analysis cannot see: `variable_instance_set`, `with` over non-constant target strings, `instance_change`, runtime reflection. Those mark the affected field `TOP` if the name appears as a string constant near them (heuristic, documented), else are listed as a known gap. Because typed access is always guarded and falls back to the same dynamic lookup a missing/incorrect fact would produce today, a wrong fact degrades to a `undefined` read or a warning, not a crash.

What we win, concretely: `owner.x` becomes `getGmlEntityField(ctx, <owner expr>, "x")` or a direct component read; `follow.y`, `target.hp` likewise; `gmlNum` wrappers become type-directed; the ~130 lines of `localEntityRefs` heuristics and `gms2-crossfile-refs.ts` are deleted; `FieldInfo.holdsEntity` is computed from the solution (`pts(field) ∩ Objects ≠ ∅`) instead of the `other.id` regex. Remaining gaps: containers, dynamic script execution, `instance_change`.

## 6. Risks and non-goals

Risks:

- Emitter volume: the ~40 rewrite families become tables; risk is silently dropping a family. Mitigation: S3 coverage test built from the old pipeline's emitted names, and golden diff.
- Golden diffs will be large at S4 (formatting, wrapper differences). Mitigation: canonicalise both outputs through TS `createSourceFile` + printer comparison in the harness, so only semantic differences require review (does NOT run repo formatters).
- Parser gaps vs real GML (project-specific syntax) show up as `ErrorStmt`; the count is a harness metric. If a project has many, add parser rules before flipping.
- Over-approximation of `with (obj)` targets includes children; changes behaviour where inheritance was previously ignored (documented, reviewed in diff).
- Flow-insensitive facts can give `pts` larger than reality: only costs precision, never correctness for typed access as designed (guarded).
- Single-owner file: `gms2-transpile.ts` must stay frozen for all other agents until S8.
- Performance: AST + solver should be faster than the O(names x passes) regex loops (measure in S5/S9; unverified).

Not done by the redesign:

- No replacement of the instance-variable side table with typed fields (a runtime/ECS change).
- No general type inference beyond instance-reference sets and the numeric/array/struct kind needed for `gmlNum`.
- Struct/ds/array element tracking (TOP by design) and `variable_instance_*` reflection.
- No fix for engine-missing APIs (R-1's `audio_emitter_create`): emits a warning stub only.
- No GML semantics not already supported by the engine (e.g. real `instance_change` in place).
- No generic legacy-regex fallback after S8.
- No new parser library, no external analysis dependency.
