# 00b Fixture triage (A2/A4): failures of the never-run fixture-gated tests

STATUS: PARTIAL (first pass; line numbers marked ~ are approximate). Read-only; no repo file besides this one touched. Fixtures cited only as real project A..G. Raw logs: scratchpad `triage/` (`smoke-*.log`, `walk-*.log`, `multi-*/`, `prof/`).

Method: per project, each test file run separately with `--reporter=verbose`; then `gms2-multi-project-walk` (generic, room-order independent) and a scratch importer run (output in scratchpad, syntax-checked with the TS parser) to see what the hard-coded tests were hiding.

## Headline

- 3 of the 5 "failing" cases are test-harness assumptions (tests are hard-wired to project A). They mask real bugs, listed below, that the generic multi-project walk shows.
- The multi-project walk (`gms2-multi-project-walk.test.ts`) treats "behavior module failed to load" as an import WARNING, not a failure, so it PASSES on D, E, F, G while 1, 20, 1, 1 behavior/script modules do not even parse. It should fail on these (see T-11).
