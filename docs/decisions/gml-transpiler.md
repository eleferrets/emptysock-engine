### GMS2 transpiler: `x`/`y` built-in position variables, input polling, and a real string-masking bug

A real, full-project `tsc --noEmit` sweep of a real project's regenerated output (1325 `TS2304`-dominated errors) found `x`/`y` as by far the single highest-frequency unresolved identifier, followed closely by `hsp`/`vsp`. Both turned out to share one root cause plus one genuinely separate gap:

**`x`/`y` map onto `Transform.x`/`Transform.y`, the same pattern `image_angle`/`image_xscale` already use.** `gms2-transpile.ts` never had _any_ rewrite for GameMaker's own most fundamental built-ins — every instance's position — because the existing generic "auto-declare on first bare assignment" pass (`identifyGmlImplicitVars`) only recognises a _plain_ `name = expr;` assignment as its signal, and real GameMaker movement code overwhelmingly writes position via `x += hsp;`, never a plain `x = ...;` — so `x`/`y` were never even added to that pass's tracked set, let alone rewritten. A new, dedicated rewrite (increment/decrement → compound → plain → bare-read, the same ordering every other built-in here uses) targets `Transform.x`/`.y` directly instead, so a GML script's `x += hsp;` moves the same position `RenderPipeline`/`place_meeting`/`CameraSystem` follow already read.

**The real, previously-undiscovered bug this surfaced: string-literal masking had no notion of a `//` comment.** Both the implicit-var pass and the new `x`/`y` pass mask every `"..."`/`'...'` literal before rewriting (so a rewrite regex can't fire inside a real string), using `/"(?:[^"\\]|\\.)*"|'(?:[^'\\]|\\.)*'/g`. Real GML comments routinely contain a lone apostrophe — English possessives/contractions (`// Taking away the player's control`, confirmed against a real project's own `obj_player/Step_0.gml`, which has half a dozen of these). An _odd_ number of `'` characters scattered across a function body's comments makes that regex's single-quote alternative pair the wrong two apostrophes — one from an early comment, the next from a much later, wholly unrelated one — and greedily swallow every real line of code in between into one fake "string literal" that sails through every rewrite pass untouched and only reappears, verbatim and unrewritten, at the final unmask step. This silently defeated the implicit-var pass for `hsp`/`vsp`/etc. across entire regions of a real function body whenever a stray apostrophe fell in a comment above them — the actual explanation for why `hsp`/`vsp` were only partially resolved despite a real rewrite pass existing for them. Fixed with a shared `maskGmlStringLiterals`/`unmaskGmlStringLiterals` helper pair that processes one physical line at a time — a `//` outside any already-open string on that line ends the line's own scannable "code" portion right there, so the comment text (apostrophes and all) can never mismatched-pair with a quote on a different line. Both call sites (the implicit-var pass, the new `x`/`y` pass) now share this one implementation.

**Keyboard/gamepad/mouse polling functions are real, in a new sibling file `compat/gmlInput.ts`.** `keyboard_check`/`keyboard_check_pressed`/`keyboard_check_released` are GameMaker's single most common input idiom (confirmed against a real project's own `scr_get_input.gml`) and had zero compat wiring anywhere, alongside the whole `vk_*`/`gp_*`/`mb_*` constant families and `gamepad_is_connected`/`gamepad_button_check`/`gamepad_axis_value`/`mouse_check_button_pressed`. Every function takes `(ctx: GmlInputContext, ...)` — the same context-only shape `gmlCamera.ts` already established for room-global (not per-instance) GameMaker state. `keyboard_check` reads `InputManager`'s own frozen `keyboard.isDown(code)` snapshot through `gmlKeys.ts`'s existing `vkToDomCode` translation; `keyboard_check_pressed`/`_released` and `gamepad_button_check_pressed` track the previous frame's down-state in a `WeakMap<Game, Map<...>>` side-table, the same up/down-transition technique `GmsProjectRuntime`'s own `_prevKeyDown` field already uses independently for its Key dispatch pass (kept as a second, intentionally separate instance of the same pattern rather than a shared one, since that field is scoped to one `GmsProjectRuntime`'s frame loop while this one has to work for any caller). `display_get_gui_width`/`_height` read `ViewportSystem.config.designWidth`/`designHeight` (one of `Game`'s five always-registered services); `application_surface` is an honest sentinel (`-1`) since this engine has no general Surface API, and `surface_get_width`/`_height` resolve it to the same GUI resolution while honestly returning `0` for any other surface id.

**`draw_set_color`** (the American-spelling alias GameMaker accepts alongside `draw_set_colour`, confirmed on the same manual reference page) is now a plain re-export in `compat/gml.ts`, and the transpiler's existing `draw_set_colour` rewrite matches both spellings. **`max`/`min`/`ord`** (compat/gml.ts, thin wrappers over `Math.max`/`Math.min`/`String.codePointAt`) were fully missing from `THREADED_PURE_FUNCTIONS` despite every other GML math built-in already being wired — `abs` was deliberately _not_ added there, since a separate, pre-existing pass already rewrites it straight to `Math.abs`. **`room`** (a bare read of the current room name, `compat/gmlActions.ts`'s new `room(ctx)`) returns `ctx.currentRoom` as-is — the same field `action_next_room`/`GmsProjectRuntime.currentRoom` already maintain — since real GML overwhelmingly compares it against a bare room-name identifier (`if (room == rm_menu)`) rather than calling a function.

**Deliberately left out of this pass, and why:** GML's `enum Name { A, B, C }` (GameMaker's own `TRANS_MODE` pattern, 16 real occurrences in a real project) needs real cross-file, project-wide name propagation — one object's Create event declares the enum, several unrelated objects reference it — which `transpileGML`'s per-file transpile shape has no mechanism for today; wiring it would need a project-wide pre-scan pass in `gms2-codegen.ts` analogous to `scanGmlImplicitVars`'s existing per-object (not per-project) scan, a genuine, separate follow-up rather than a same-pass regex fix. `obj_input.key_right`/`obj_player.hsp` and similar dotted references to _another_ instance's field are the same already-documented, deliberately-unresolved "this transpiler cannot resolve which entity a name like `inst`/`other`/a named other-object singleton refers to" gap `sprite_index`/`image_*`'s own dotted-reference guard already establishes — not a new limitation. `draw_set_halign`/`fa_center`/`draw_sprite_part_ext` (text alignment, partial-sprite drawing) and `e__VW`-prefixed legacy GameMaker view-script internals were left unwired — genuinely deeper features (this engine's `GmlDrawTarget` has no halign concept, and `gms2-sprite-import.ts` only ever converts a sprite's first frame) rather than same-shape gaps.

### GMS2 transpiler: `getGmlVar`/`getGmlObjectVar` bare reads are `unknown` by design, so a real `gmlNum()` runtime coercion — not a TS-only `as number` cast — is what makes generated code actually typecheck

A real, full-project `tsc --noEmit` sweep against a real project found the single largest error category by far (`TS2571`/`TS2345`/`TS18046`, several hundred error lines) was every bare read of a GML instance variable — `(GmlActions.getGmlVar(_entity, _ctx, "grav"))`, `obj_input.key_left` via `getGmlObjectVar` — used directly in arithmetic/comparison position. `getGmlVar`/`getGmlObjectVar` return `unknown` by design (see `compat/gmlInstanceVars.ts`'s own doc comment — GML instance variables are genuinely dynamically typed, and this codebase already established elsewhere that pretending otherwise would misrepresent them), but a bare read used in expression position had no cast/coercion of any kind, unlike the compound-assignment/increment passes right next to it, which already applied `as number | undefined ?? 0`.

The first fix attempted was the same `as number` TypeScript-only type assertion the compound-assignment pass already used. That broke a real, pre-existing codebase testing convention: this file's own transpiler test suite proves many rewrites via `new Function(out)` — a genuine plain-JS syntax-validity check, documented in several tests' own comments as "a real syntax-validity proof, matching this file's own existing pattern." A bare `as number` is valid TypeScript (stripped at a real build step) but a hard `SyntaxError` under plain JS `eval`/`new Function`, so it broke that guarantee for every rewrite exercising a bare instance-variable read — a real regression, caught by running the full test suite rather than trusting the `tsc` sweep number alone.

The real fix: `compat/gmlInstanceVars.ts`'s new `gmlNum(value: unknown): number` — a genuine runtime coercion (`typeof value === "number" ? value : Number(value) || 0`), not a type-only assertion. It passes an already-numeric value through unchanged (the overwhelmingly common real case) and coerces anything else, falling back to `0` for something `Number()` can't make sense of — matching GML's own loosely-typed runtime, which performs the same implicit coercion in arithmetic position rather than statically rejecting it. Unlike `as number`, a call expression is valid plain JS both before and after a TypeScript build step strips type-only syntax, so it satisfies `tsc` _and_ keeps every `new Function(out)` runnability test passing. `gms2-transpile.ts`'s bare same-instance read (`GmlActions.getGmlVar(...)`) and cross-instance read (`GmlActions.getGmlObjectVar(...)`) rewrites both wrap through `GmlActions.gmlNum(...)`; `gms2-codegen.ts`'s legacy `argument[N]`/`argumentN` rewrite (see below) does the same for `args[N]` (typed `unknown[]`).

A second, much smaller-but-related fix: `buildScriptModule`'s generated parameter list (`gms2-codegen.ts`) typed every named GML script parameter (`function scr_screen_shake(magnitude, frames)`) as `unknown`, causing the identical error category the moment a script's own body used a parameter arithmetically — real, confirmed, and the majority real case (`scr_screen_shake`'s own `argument0 > shake_remain` comparison). Parameters are now typed `number` directly in the generated signature (not wrapped in `gmlNum` at every use site, since a function _parameter_'s own declared type is the correct place for this, unlike a `getGmlVar` call whose return type can't be narrowed at the declaration) — the same honest, already-precedented assumption, stated plainly in the generated signature rather than at every call site.

A third, independent fix in the same pass: GameMaker's legacy `argument`/`argumentN`/`argument[N]`/`argument_count` idiom (predating GMS2.3 named parameters) was only ever rewritten when a script had _no_ `function name(...)` wrapper at all (`extractScriptSignature`'s `isLegacyArgStyle` flag) — but a real script can declare `function name() { ... }` with zero named parameters while its body still uses the legacy idiom throughout, confirmed real in a real project's own `scr_slide_transition.gml`. The rewrite now also fires whenever a script declares zero named parameters, regardless of `isLegacyArgStyle`, since a script with real named parameters can never legally contain a bare `argument`/`argumentN` reference in valid GML, so this never misfires. `argument[N]` (bracket-index legacy syntax, GameMaker's own documented equivalent to `argumentN`), a bare `argument` (the whole legacy arguments array), and `argument_count` (`args.length`) are all real, newly-wired rewrites — previously all three were unrewritten `Cannot find name` identifiers.

### GMS2 transpiler symbol pre-scan: stayed regex-based, real research behind the decision — plus a real double-wrap bug the research surfaced and fixed

Researched (WebSearch, not assumed) whether a real, maintained GML parser/lexer exists that could replace this transpiler's hand-rolled per-file regex passes with a real AST for at least the project-wide symbol pre-scan (`gms2-enums.ts`'s `scanGmlEnums`, the object-name/cross-instance detection the "real cross-instance references" section above documents). Three real candidates found: `@bscotch/gml-parser` (npm, actively published — v1.17.2 at research time, ~8 months old — the maintained successor to Bscotch's own retired Stitch CLI, models a whole GMS2/2.3+ project including structs/statics/constructor methods, real position-tracked AST), `gamemaker-language-parser` (Pizzaandy, Antlr4-generated, WIP Prettier plugin — real but pre-1.0 and tooling-focused, not published as a stable consumable library), and `gml-pegjs` (ThomasHickman, explicitly experimental, unmaintained).

`@bscotch/gml-parser` is the one real, suitable, maintained option. **Decision: do not adopt it this pass, for real reasons, not "no library exists":** (1) it models a whole GameMaker _project_ (its own resource graph, `.yyp` conventions, reference tracking) — a much larger surface than this pass needs, and integrating it correctly would mean either running two independent project-model passes (this importer's own `gms2-*-import.ts` family plus `@bscotch/gml-parser`'s) that have to agree on project state, or replacing this importer's own already-real, already-tested `.yyp`/`.yy` parsing (`gms2-parse.ts`, CLAUDE.md's own extensively-documented quirks list above) with its equivalent — a materially larger, riskier rewrite than "swap the pre-scan." (2) This transpiler is 15+ interdependent regex passes verified end-to-end against a real, full GameMaker project (one) with two full `tsc --noEmit` sweeps' worth of real regressions found and fixed; a pre-scan built on a genuinely different parser (its own tokenizer, its own notion of scope/identifiers) risks disagreeing with what the regex passes downstream already assume about masked strings/comments (`maskGmlStringLiterals`) and identifier boundaries, for a project that already imports and transpiles correctly. (3) No sandboxed way in this pass to add and pin a new npm dependency's exact version against a real end-to-end proof it doesn't regress the existing 409-test toolchain suite — a real, unvalidated risk, not a hypothetical one, and this codebase's own precedent (e.g. the deterministic-Rapier-build entry, the "unvalidated perf-risk rendering path" reasoning in the scene-transition entry above) is to not ship an unvalidated swap when the existing, tested path works. Revisit if a future pass needs true AST-level transforms (the enum/static passes are already closer to that need than the per-line rewrites are) and has room for a real, isolated proof-of-concept against the full a real project regression suite before landing it.

**What was built instead: closed a real, concrete symbol-table bug the research pass's own re-reading of the pre-scan code surfaced** — not a new hand-written scanner class (the existing `_objectNames`/`_enumNames` module-level sets, `maskGmlStringLiterals`-respecting per-file regex passes, and the dotted-reference/known-name guards documented in the "real cross-instance references" section above were re-read and found structurally sound for every real case in a real project; inventing a second, parallel scope-tracking mechanism on top of an already-correct one would be exactly the kind of ungrounded rewrite item 1's own research explicitly argues against). The real bug: the implicit-array-variable detection pass (`gms2-transpile.ts`, right before the instance-variable pass) and the pre-existing `[| i]`/`[? key]` ds_list/ds_map accessor rewrite pass could double-fire on the same name — `list[| 0] = 5;` (accessor pass strips `| ` to plain `list[0]`, which the array-var pass then correctly identifies as an undeclared implicit array and wraps in `GmlActions.getGmlArrayVar`) produced a **nested** `getGmlArrayVar(_entity, _ctx, "getGmlArrayVar(_entity, _ctx, "list")")` — because the array-var pass's own three sub-passes (indexed-assignment, indexed-read, bare-whole-array-read) run sequentially against the same progressively-rewritten string, and the third (bare-read) sub-pass re-matched the quoted `"list"` text an earlier sub-pass in the same loop iteration had just inserted. Fixed with a `(?<!_ctx, ")` fixed-length negative lookbehind on all three sub-passes, so a sub-pass never re-matches text a sibling sub-pass in the same loop iteration already generated. A second, related guard (`(?!\s*[|?])` on the array-var detection/read regexes) keeps a genuine ds_list/ds_map accessor on the same name from ever being misidentified as a plain array index in the first place. Both confirmed via a real full-project sweep: 432 → 413 `tsc --noEmit` error lines (this file's last documented count re-verified fresh). Tests: `gms2-transpile.test.ts`'s ds_list `[| i]` accessor test updated to assert the correct (previously double-wrapped, now singly-wrapped) real output.

### GMS2 source bugs: named in the report, emitted defined-safe (`gms2-source-bugs.ts`)

`scanGmlSourceBugs()` runs once before any file is transpiled (`gms2-import.ts`, after the asset registries) and finds names the original project uses but never defines. Text-level analysis (comments/strings stripped, `with` bodies skipped because their names belong to the target instance, names assigned inside any `with` body project-wide counted as assigned, macros/enums/`globalvar`/assets/GML built-ins excluded): (1) `unset-variable`: an object's event code reads a bare instance variable that nothing in its `parentObjectId` chain assigns (event files, Variable Definitions); (2) `missing-font`: `draw_set_font(x)` with no such font; (3) `missing-sprite`: a sprite argument (`draw_sprite*`, `action_sprite_set`, `sprite_index =`, or a script parameter whose `@param` doc name starts with `spr`/`sprite`) with no such sprite; (4) `missing-object`: an object argument of a spawn/collision call with no such object. Each becomes a named entry in `migration-report.md` ("Source bugs (defects in the original project)") with `file:line`, what was wrong and what was emitted. Emission: unset variables are registered as implicit instance variables for that object (`setGmlUnsetVarsByObject`, read by `buildObjectBehavior`), so reads go through `getGmlVar`/`gmlNum` and are a defined `0`, and the behavior module gets a `// [source bug]` header; missing fonts resolve to the bare font id string (the engine draws an unregistered id with its default font); missing sprites resolve to a generated 16x16 magenta/black placeholder at `assets/sprites/__missing_sprite__/frame_0.png` (`buildMissingSpritePng`, written only when needed; all three sprite-quoting sites go through `spriteTexturePath`); missing objects resolve to the quoted name (spawns warn and return no instance). The scan is conservative, not a GML type checker: a real GML built-in missing from `GML_BUILTIN_VALUES` would be reported as an unset variable and read as `0` (it would have been a `ReferenceError` anyway); add it to the list.

Two related fixes found while tracing a real project's "dormant bugs": (a) the earlier claim that `hp` (`obj_bullet`) and `bullet_tolerance` (`obj_player`, `obj_Egun`) are never assigned was wrong. Both are read inside `with (<expression>) { ... }` bodies that run against another instance (`with (instance_place(x, y, obj_pShootable)) { hp--; }`, `with (bullet) { ... random_range(-bullet_tolerance, ...) }`), where the target does define them. The transpiler now seeds any project-wide instance-variable name a `with` body mentions into the function's implicit variables (`extractGmlWithBodies`, the `with (<expression>)` block in `transpileGML`), so those reads/writes resolve through the side-table on the with-rebound `_entity` instead of staying bare identifiers. (b) `buildObjectBehavior` now also unions variables assigned by ancestor objects' event files into the child's implicit variables (a child instance owns everything its parent chain sets). a real project's real findings after this: `zoom` (`obj_player_stats/Create_0.gml:11`, set only by `obj_display_manager`), `key_right`/`key_left` in `obj_slideblock`/`obj_moveblock` `Collision_obj_tplayer`, missing font `font0` and missing sprite `sTextbox` (`oTextbox/Draw_64.gml`). Tests: `gms2-source-bugs.test.ts`.

### `_other` dotted access routes to `getGmlEntityField`/`setGmlEntityField`, not `getGmlRefVar`

In `transpileGML`'s local-entity-ref pass (`localRefNames`), a dotted access on `_other` (`other.image_angle`, `other.hp`) is deliberately emitted as `GmlActions.getGmlEntityField(_ctx, _other, "field")` / `GmlActions.setGmlEntityField(_ctx, _other, "field", expr)`, while every other name in that set (same-function local entity refs, cross-file entity-ref fields) keeps `getGmlRefVar`/`setGmlRefVar(_entity, _ctx, "varName", "field")`. Reason: `_other` is always a live `Entity` wherever it appears (`gms2-codegen.ts` gives every `onCollideWith<Other>` a real `_other` parameter and the `with` rescoping binds `const _other = _withCaller;`), so there is no `(entity, varName)` indirection to resolve; the `*RefVar` pair first reads a local variable holding the entity and would look up a variable literally named `_other`. Both families store through the same per-`(World, eid)` side-table (x/y via the real `Transform`), so a value written through one is visible through the other. An earlier code comment near the `localRefNames` block still said `_other` went through `getGmlRefVar`; it now names the real routing. No behaviour change.

### GML parser and symbol table: hand-rolled lexer + Pratt parser, standard library only (`packages/toolchain/src/gml/`)

Decision (the user's, following `docs/research/01-gml-parse-symbol-table.md`): a hand-rolled lossless lexer plus recursive-descent/Pratt parser with statement-level error recovery, not `@bscotch/gml-parser` and not a Lezer grammar. This is the "revisit if a future pass needs AST-level transforms" the pre-scan entry above left open; the constraint that entry named (two tokenizers disagreeing) is met by owning the tokenizer and migrating the regex passes one at a time behind parity tests.

Shape: `lexer.ts` (every source character belongs to exactly one token, trivia included, so `printTokens(tokenize(s)) === s`; handles `#macro` with `\` continuations, `#region` lines as trivia, `$FF`/`0x`/`0b`, `@"verbatim"`, `$"template {expr}"`, accessor openers `[| [? [# [@ [$`), `ast.ts`, `parser.ts` (never throws: a statement that fails to parse becomes an `ErrorStmt` and parsing resumes at the next `;`, stray closer or line-leading statement keyword), `builtins.ts` (+ `builtins-data.ts`: the single table of keywords, built-in variables, threaded compat calls, constant families, object/sprite argument positions, entity-returning calls; tests assert it covers every list still living in `gms2-transpile.ts`/`gms2-source-bugs.ts` and that every named runtime export exists on the engine), `symbols.ts` (`Scope`, `Symbol`, resolution order: block, function locals/params, `with`/struct/object instance fields, project function/asset/enum/macro, builtin), `project-symbols.ts` (`buildProjectSymbols`/`analyzeFile`, a pure function with no module-level state).

GML quirks encoded in the parser: `=` is assignment only in statement position and a comparison anywhere inside an expression (`if (a = b)`, `x = (a = b)`, call arguments); conditions may omit parentheses and take an optional `then`; `begin`/`end` are braces; semicolons are optional; `if (a) (b).c = 1;` is not parsed as a call; member names and struct keys are never identifier references (this removes the `(?<!\.[ \t]*)` dotted-guard bug class by construction). `???` is not a GML operator: it lexes as `??` then `?`. A `[$` immediately followed by a hex digit is an array literal starting with a `$` hex number, otherwise the struct accessor.

Scope of the migration and its rule: each step replaces a name list or regex guard only where the symbol table gives identical or strictly more correct results, verified by running the old and new paths over the existing test fixtures.
